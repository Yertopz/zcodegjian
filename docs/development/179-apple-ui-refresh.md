# 工作区界面视觉约束

本规范约束共享 UI 的视觉和基础交互，适用于桌面和 Web。以 `DESIGN.md` 的语义色、字号、圆角和高密度工作流规则为准，遵循 Baseline UI 的组件复用、键盘可访问性及克制视觉原则。

## 范围与职责

- `packages/ui/src/styles.css` 负责共享字体栈和浅色、深色主题的结构表面；主题选择和持久化仍由现有主题机制管理。
- 登录入口和聊天输入壳负责各自的布局与视觉层次；登录、草稿、拖放、发送和错误状态继续由现有组件与服务管理，不引入新的状态所有者或跨模块接口。
- 新建任务入口使用原生按钮；鼠标、Enter 和空格共用现有的草稿创建路径。禁用时原生禁用状态阻止触发，保留现有提示和测试标识。
- 只调整视觉表现，不迁移用户数据、主题设置或会话状态；平台特定窗口区域和移动端布局继续使用原有边界。

## 设计与验收

- 使用系统无衬线字体和既有 `text-ui-*` 字号，保留用户界面字号设置以及独立的代码和终端字体设置。
- 浅色和深色主题以背景、侧栏、面板、输入框和边框形成克制的层次；状态色和操作颜色仍使用现有语义 token。
- 弱提示、占位符和快捷键使用可读的三级文字颜色，不依赖极低透明度表达层级。
- 聊天输入区保持清晰的边界及悬停、聚焦和拖放反馈；触屏工具栏保留至少 44px 的命中区。
- 登录面板在窄屏可滚动，主要操作保持足够的高度；授权、取消、错误和 API Key 入口的行为与可访问名称不变。
- 键盘焦点须可见，普通主题使用语义蓝色描边，系统强制颜色模式使用系统高亮色；焦点不清除菜单、对话框等表面原有阴影。
- 登录页使用语义表面与文本层级，避免装饰渐变和无必要的字距调整；现有品牌标识和登录选项保持可辨识。
- 草稿首页以居中问候语为视觉中心，标题适应可用宽度；工作区选择位于输入卡片下方，输入区不显示推荐提示词按钮。
- 仅使用颜色等轻量过渡，不引入持续动画；验证浅色、深色、桌面和窄屏，并检查现有键盘和拖放交互。

## 运维与后续开发

主题颜色集中维护于 `styles.css`，不要在业务组件中复制浅色或深色固定色值。改动结构表面后应检查侧栏、弹层、终端、输入区以及两种主题的文字对比。布局和样式改动应执行 UI 类型检查、格式检查，并在可运行的桌面或 Web 环境进行视觉验收；未完成的验收须在交付时说明。
