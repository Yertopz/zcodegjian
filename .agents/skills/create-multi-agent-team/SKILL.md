# 创建多智能体团队

用 `CreateAgent` 创建的每个成员都是**长期同伴**，不是一次性子任务：它们的定义会落盘为用户级 agent 文件（`<storageRoot>/agents/<name>.md`），在群聊视图中以「头像 + 名字 + 简称」出现。所以每个成员必须**针对性编写**，禁止一句话提示词。

## 创建前：先出分工表

动手创建前，先向用户展示分工表并等确认：

| 成员名 | 职责 | 需要的工具 | 权限模式 | 颜色 |
| ------ | ---- | ---------- | -------- | ---- |
| code-reviewer | 审查代码缺陷与回归风险 | Read, Grep, Glob | plan | blue |
| test-runner | 运行并修复测试 | Bash, Read, Edit | auto | green |

- 名字用小写连字符（`docs-writer`），不得与内置 agent（`general-purpose`、`Explore`）重名。
- 团队规模以任务为准：3 人以内优先，成员越多 @ 额度消耗越快。

## 每个成员的五项必写项

### 1. systemPrompt（详细提示词，不是一句话）

必须包含五段，缺一段就补齐再创建：

1. **角色定位**：一句话说清这个成员是什么专家。
2. **负责领域**：列出它应该处理的具体任务类型。
3. **明确边界（不做什么）**：例如「不修改文件，只报告发现」「不直接执行命令，产出脚本由 test-runner 执行」。边界缺失是成员越权的最大来源。
4. **协作接口**：什么情况下 @ 哪个成员、传什么内容。例如「发现测试失败时 @test-runner，附上失败摘要与复现命令」。
5. **输出格式**：约定回传结构（如「按 严重程度 / 位置 / 修复建议 三列输出」），让主智能体可以直接汇总。

### 2. description（一句话简称）

会显示在群聊名字右侧，写清「干什么」，不超过一句话。例：`审查代码缺陷与回归风险`。

### 3. tools（最小权限白名单）

- 按职责精确选择，**不要省略**（省略会继承默认工具集，等于全量放权）。
- 只读分析成员（审查、检索、规划）不给 Write / Edit / Bash。
- 需要 shell 的成员明确列出，并考虑 permissionMode 是否相配。

### 4. permissionMode（权限模式）

- `plan`：只读成员、任何不该改文件的角色。
- `auto`：需要写文件、跑命令的执行成员。
- 缺省 = 继承会话默认；不确定时宁可 `plan`。

### 5. color（头像颜色）

每个成员不同颜色，便于群聊区分：red / blue / green / yellow / purple / orange / pink / cyan。

## 创建后：分派与协作

- 用 `SendMessage` `@成员名` 分派首个任务；任务描述里带上它需要的上下文（文件路径、约束、验收标准），成员看不到你创建它时的思考过程。
- @ 次数是团队共享额度（默认上限见设置页）：批量任务合并成一条消息投递，不要一来一回挤额度。
- 成员之间是同伴：可以互相 @ 协作，但任何成员都不能再派生子智能体（工具层已结构性禁止，无需在提示词里重复约束）。
- 收到回传后核对结果与任务要求是否一致，再继续分派或向用户收口。

## 调用示例

```json
{
  "name": "code-reviewer",
  "description": "审查代码缺陷与回归风险",
  "systemPrompt": "你是代码审查专家。\n\n职责：...\n\n边界：不修改任何文件，只报告发现。\n\n协作接口：...\n\n输出格式：按严重程度/位置/修复建议三段输出。",
  "tools": ["Read", "Grep", "Glob"],
  "permissionMode": "plan",
  "color": "blue"
}
```
